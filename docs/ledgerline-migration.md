# Ledgerline migration integration

The Ledgerline property maps to `HighVolt-Analytics/Ledgerline`, branch `main`, workflow `deploy.yml`, and the production target. The server-side API returns HTTP 423 before contacting GitHub unless the independent Vercel production variable `LEDGERLINE_PORTAL_DISPATCH_ENABLED` is exactly `true`. A future dispatch request must provide a 40-character release commit and the exact `DEPLOY` confirmation; the Ledgerline workflow independently checks both against the dispatched `main` commit and requires its repository-level manual authorization gate. Automatic deployment uses a separate GitHub variable and cannot be enabled by the portal gate.

The portal retains Microsoft Entra sign-in and the server-side `ALLOWED_EMAILS` allowlist. The dashboard, status API, and dispatch API enforce authenticated allowlisted sessions. Dispatch POSTs also require a same-origin browser request, accept only a known project id, and reject caller-supplied repository, branch, workflow, environment, or other unexpected fields.

GitHub API calls use the existing server-side `GITHUB_TOKEN` through a server-only Octokit module. The token is never returned by an API or included in application logs. Workflow history requires Actions read access, and dispatch requires Actions write access on each repository the portal is allowed to deploy. Keep the token value in Vercel's server-side environment only; do not prefix it with `NEXT_PUBLIC_`. The portal does not use `GITHUB_OWNER` to route requests: owners, repository names, workflow files, and branches come from the fixed server-side website map.

The Vercel variable `LEDGERLINE_PORTAL_DISPATCH_ENABLED` and the Ledgerline repository variable of the same name are distinct settings and must be configured consistently through their official interfaces. Keep the portal variable false until the repository's independent manual gate is approved and active. The temporary `LEDGERLINE_PRODUCTION_CUTOVER_ENABLED` value does not authorize automatic push deployments. Vercel deployment protection does not substitute for source-level session and allowlist checks.
